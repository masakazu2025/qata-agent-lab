# 用語集を二つに分け、一般の言葉にそろえる

## 目的

qata の用語集 `docs/knowledge/glossary.md` には、qata の中でしか通じない言い方が多い（「偽物」「端から端までのテスト」「周回」「変換の枠」など）。用語集に載ったことで、それが正式な言葉になり、ほかの文書にも広がっていた。初めて読む人は、用語集を引かないと文書が読めない。

元をたどると、AI が「文書は日本語で書く」を、技術用語まで訳すことと受け取ったのが始まり。CI を「関門」、インターフェースを「境目」と書いた。

この変更で、次のようにする。

- 用語集を、qata 固有の言葉（`glossary/domain.md`）と、一般の言葉の推奨語（`glossary/general.md`）に分ける。
- 一般の言葉で言い換えられるものは、よく使われる言葉（モック・E2E テストなど）に置き換える。
- 「実行」「結果」のように、一語では何のことか決まらない言葉は、用語集から外す。
- ルールに、技術用語は訳さないことを書く。

## 前提

この指示書は、文書（`.md`）だけを変える。コード・設定・画面の文字・テスト（`.py`・`.ts`・`.tsx`・`.feature`・`.json`・`.yaml`・`.yml` など）は変えない。

始める前に、本物の qata で次を確かめる。合わないところがあれば、そこは入れずに人に聞く。

- 親 `qata` に、用語集が一つのファイル `docs/knowledge/glossary.md` としてある。
- 用語集に、下の「置き換える言葉」の表の左の言葉が、項目としてある。
- 用語集の「人の確認」と「承認」が、別々の行になっている（「人の確認」＝実行の前に人がテストケースを見て承認すること、「承認」＝人の確認を済ませること）。
- `.claude/rules/general/working.md` に「文書は日本語で書く。」の一行がある。
- `.claude/rules/qata/knowledge.md` に「新しい言葉を使い始めたら、用語集に足す」とある。
- 「関門」「部品」「部品の辞書」「契約」は、この指示書では扱わない（別の指示書で扱う）。用語集の中の項目も、そのまま `domain.md` に移す。

## 手順

### 1. 一般の言葉に置き換える

親 `qata` と子（`qata-runner`・`qata-server`・`qata-web`）の、すべての文書（`.md`）で置き換える。過去の記録（`docs/decisions.md`・`docs/retro.md`・`docs/reviews/`・`docs/ideas.md`）も置き換える。子の `qata-contracts/` は親の写しなので除く（5 を見る）。

| いまの言葉 | 新しい言葉 |
| --- | --- |
| 偽物・偽の〜・偽と・偽は・偽に・偽で | モック・モックの〜・モックと・モックは・モックに・モックで |
| 端から端までのテスト | E2E テスト |
| 周回 | イテレーション |
| 最初の周回・N 周目 | 最初のイテレーション・N 回目のイテレーション |
| 立て直し・立て直す | 復旧・復旧する |
| 始める前の状態 | 事前条件 |
| 取り消しシナリオ | 復旧の手順 |
| 有効な版 | 対象バージョン |
| スクショ | スクリーンショット |
| 確認事項 | 期待結果 |
| 人の確認 | 承認（「承認」にまとめる） |
| 確認待ち（承認の状態） | 承認待ち |

### 2. qata 固有の言葉の名前を変える

| いまの言葉 | 新しい言葉 | 置き換える場所 |
| --- | --- | --- |
| 変換の枠 | 変換ルール | すべて |
| 読み方（画面の文字を読む手段。`source.method`） | 文字の取得方法 | その意味で使っているところだけ。「ファイルの読み方」「エラーの読み方」「契約の読み方」など、別の意味のものは変えない |

### 3. 機械的に置き換えると、文が崩れるところ

一括で置き換えたあと、次の言い方は手で直す。ほかにも、変わった行はすべて読んで、文が通じるかを確かめる。

| 置き換えたあと | 直した文 |
| --- | --- |
| 確認事項が合わなくても | 期待結果と違っても |
| 人の確認を減らすための仕組み（`.claude/rules/general/autonomy.md`。機能の名前ではなく、人が確かめる手間のこと） | 人が確かめる手間を減らすための仕組み |
| 人の確認（チェックボックス）は `needs_review` | 承認が要るか（チェックボックス）は `needs_review` |
| 人の確認の印 `needs_review` | 承認が要るかの印 `needs_review` |
| 人の確認（承認）を要るかどうか選ぶ | 承認が要るかどうかを選ぶ |
| 人の確認（承認）・人の確認が要る | 承認・承認が要る |
| 人の確認あり・人の確認なし（用語集の図） | 承認が要る・承認が要らない |
| 「確認は要らない」・人の確認を飛ばす（`docs/retro.md`） | 「承認は要らない」・承認を飛ばす |
| 変える規則は server の変換ルールに置く（規則とルールが重なる） | 変える規則（変換ルール）は server に置く |
| Playwright（端から端まで） | Playwright（E2E テスト） |
| 端から端までは、（`qata-web/README.md`。テストのこと） | E2E テストは、 |
| 止まったら、取り消しシナリオを流して立て直す（`docs/roadmap.md`） | 止まったら、復旧の手順を流して元に戻す（「復旧の手順を流して復旧する」と重ならないように） |
| 始める前の状態に戻った?（`docs/knowledge/automation-pitfalls.md` の図） | 事前条件の状態に戻った? |
| 「始める前の状態」を書き、立て直しのあとで、そこに戻ったかを | 「事前条件」を書き、復旧のあとで、その状態に戻ったかを |
| 各テストに始める前の状態を書き、戻ったかを | 各テストに事前条件を書き、その状態に戻ったかを |
| 止まったら立て直し、・止まったテストを立て直し、 | 止まったら復旧し、・止まったテストを復旧し、 |
| 有効な版の話の中の「この版から」「この版まで」「古い版」「版の形式」、タグの例の「対象アプリの版」（`docs/roadmap.md`） | 「このバージョンから」「このバージョンまで」「古いバージョン」「バージョンの形式」「対象アプリのバージョン」 |
| web のE2E テスト（ひらがなと英字が詰まる） | web の E2E テスト（英字の前に半角の空白を入れる。qata の文書の書き方） |

「端から端まで一本通す」「端から端までつなぐ」のように、テストの名前ではなく普通の言い回しとして使っているところは、そのまま残す。

「版」のうち、契約の版（「契約の版」「版の固定」「正の版」など）は対象アプリのバージョンではないので、変えない。

「基本の操作」は、用語集から項目を消すだけで、文書の中では普通の言葉として残す。

### 4. 用語集を二つに分ける

`docs/knowledge/glossary.md` を `docs/knowledge/glossary/domain.md` に移し（`git mv`）、新しく `docs/knowledge/glossary/general.md` を作る。

**`domain.md`（qata 固有の言葉）**

- 題を「用語集（qata 固有の言葉）」にし、冒頭に次を書く。
  - ここに載せるのは、qata の外では同じ意味で通じない言葉だけ。一般の言葉で言い換えられるなら、ここには足さずに、その言葉を使う。
  - 一般の言葉の推奨語は `general.md` にある。
- 次の項目を**消す**（一般の言葉か、一語では何のことか決まらない言葉）：テストケース・ステップ・手順・期待結果・タグ・有効な版・クローン・実行・結果・基本の操作・立て直し・始める前の状態・偽物・端から端までのテスト・周回・セッション・issue・外。
- 消す項目にあった契約の名前は、残す項目に寄せる。
  - 「アクション」：「テストケースに書けるステップの種類。いまは、手順（キーを押す・タップする）と、期待結果（読んだ文字の完全一致、D17）」、契約は「`type`（`press_key`・`tap`・`expect_text`）」。
  - 「結果」の代わりに「実行結果の状態」を置く：「テストケース全体は 通った・落ちた・エラー、ステップはそれに「飛ばした」が加わる」、契約は `passed`・`failed`・`error`・`skipped`。
- 残す項目を、次のように直す。

  | 項目 | 直した中身 |
  | --- | --- |
  | 承認 | 「人の確認」の行を消して一行にまとめる：「実行の前に、人がテストケースを見て承認すること。要るかどうかはチェックボックスで選ぶ。状態は、不要・承認待ち・承認済みの三つ」、契約は「`needs_review`、状態は `not_required`・`pending`・`approved`」 |
  | 変換ルール（もとは変換の枠） | 「server が、部品の名前をキー・座標・文字の取得方法などに変えるための規則。汎用の規則（キー、座標のタップ、UI Automation で読む）は server に置き、それ以外は内製のツールで足せるようにする（D14）」 |
  | 文字の取得方法（もとは読み方） | 「画面の文字を取得する手段。いまは UI Automation だけ（D17）」 |
  | 復旧の手順（もとは取り消しシナリオ） | 「テストが止まったあとの復旧（3 段で行う、automation-pitfalls.md）の最初の段で流す、状況に合った汎用の操作の並び（まだない）」 |
  | idea（もとは issue・idea） | 「次回以降の改善案。親の `docs/ideas.md` に置く。やると決めたものは issue にする（D11）」 |
  | qata の範囲外（もとは外） | 「判断（テストの中身を考える、次にすることを決める、不具合を報告する）は、qata の範囲外の AI か人が行う（D39）」 |

- 残す項目：元の日本語・アクション・部品・部品の辞書・関門・承認・実行結果の状態・変換ルール・文字の取得方法・スクリーンショットの範囲・復旧の手順・契約・親・子・idea・qata の範囲外・切り出す道具。「言葉のつながり」の図と「この先増える種類」の表も残す（図の「基本の操作」は「キー・タップ・文字の取得」にする）。
- フォルダが一段深くなるので、相対のリンクに `../` を一つ足す（`app-traits.md` → `../app-traits.md`、`../../contracts/` → `../../../contracts/`）。

**`general.md`（一般の言葉の推奨語）**

題を「用語集（一般の言葉の推奨語）」にし、冒頭に次を書く。

- 一般の言葉で、言い方がいくつもあるものについて、このプロジェクトで使う言葉を決める。意味は書かない。
- 技術用語は、広く通じる言い方をそのまま使う。英字やカタカナの言葉も避けない。日本語に訳した言葉を作らない（`working.md`）。
- 言い方が一つしかない一般の言葉と、「実行」「結果」のように一語では何のことか決まらない言葉は、載せない。
- 揺れを見つけたら、ここに足す。
- qata 固有の言葉は `domain.md` にある。

表は「推奨語・使わない言い方」の二列。中身は 1 の表から作る：モック／偽物・偽の〜、E2E テスト／端から端までのテスト、イテレーション／周回・N 周目、復旧・復旧する／立て直し・立て直す、事前条件／始める前の状態、対象バージョン／有効な版、スクリーンショット／スクショ、期待結果／確認事項。

### 5. ルールと、用語集を指すところを直す

| ファイル | 変えること |
| --- | --- |
| `.claude/rules/general/working.md` | 「文書は日本語で書く。」を、「文書は日本語で書く。日本語にするのは文で、技術用語ではない。」にし、その下に二つ書く：「広く通じる技術用語は、訳さずにそのまま使う（CI・E2E テスト・pull request・モック・スキーマ・ツール・バージョンなど）」「訳した言葉を作らない（例：CI を「関門」、インターフェースを「境目」、バージョンを「版」、コピーを「写し」と書く）」。汎用のルールなので、qata の名前は書かない |
| `.claude/rules/qata/knowledge.md` | 「文書・コード・画面の言葉は、用語集（`docs/knowledge/glossary.md`）に合わせる。新しい言葉を使い始めたら、用語集に足す。」を、二つの用語集の説明にする：`domain.md` は qata 固有の言葉を使い始めたら足す（足すのは qata の外に同じ意味の一般の言葉がないときだけ）、`general.md` は揺れを見つけたら足す、一語では決まらない言葉はどちらにも載せない |
| `docs/knowledge/README.md` | 表の `glossary.md` の行を、`glossary/domain.md` と `glossary/general.md` の二行にする |
| `docs/decisions.md` | いちばん上に、決めたことを一件足す（題の例：「用語集を、qata 固有の言葉と一般の言葉の推奨語に分け、技術用語は訳さない」。決めた人は人）。中身は、この指示書の目的と 1〜4 の要点 |

親の `contracts/README.md` も置き換えの対象（スクショ・変換の枠・確認事項・読み方が出てくる）。子の `qata-contracts/` は親の写しなので、手で直さない。

- 親の `contracts/README.md` を変えたら、`.claude/rules/general/git.md` の「版の上げ方」に従い、契約の版の三つ目（説明の文だけ）を上げ、`contracts/CHANGELOG.md` に書く。
- 子の `qata-contracts/` は、次にその子を触るときに、写す道具で上げる。

### 6. リンクを直す

見出しの言葉が変わると、その見出しを `#` で指すリンクが切れる。用語集を移すと、`glossary.md` を指すリンクも切れる。置き換える前と後で、文書の中の `[...](ファイル#見出し)` が指すファイルと見出しがあるかを確かめ、切れたものを直す。

元の作業では、`docs/retro.md` から `docs/decisions.md` の D49 を指すリンクが切れた。

- 前：`decisions.md#d49-管理の拡張の-1-周目はタグと絞り込みだけにする`
- 後：`decisions.md#d49-管理の拡張の-1-回目のイテレーションはタグと絞り込みだけにする`

## 確かめ方

- 親と子の文書（`.md`。子の `qata-contracts/` は除く）に、次の言葉が残っていない。

  ```
  grep -rn --include=*.md -E "偽|端から端までのテスト|周回|周目|立て直|始める前の状態|取り消しシナリオ|有効な版|スクショ|変換の枠|確認事項|人の確認|確認待ち|アプリの版|拡張点|glossary\.md" --exclude-dir=qata-contracts --exclude-dir=node_modules .
  ```

  出てよいのは、古い言葉をわざと書いているところだけ：`general.md` の「使わない言い方」の列と、5 で `docs/decisions.md` に足した一件。

- 「読み方」が残っているところは、どれも画面の文字を読む手段以外の意味である（ファイルの読み方・エラーの読み方・契約の読み方など）。
- `docs/knowledge/glossary/` に `domain.md` と `general.md` があり、`docs/knowledge/glossary.md` はない。
- `domain.md` に、4 で消すとした項目がなく、「承認」の行に `needs_review` と三つの状態がある。
- `general.md` が「推奨語・使わない言い方」の表で、意味を書いていない。
- 文書の中のリンク（ファイルと見出し）が、置き換える前より増えて切れていない。
- 変わった行を読んで、文が通じる。特に、3 の表の言い方。

コード・設定・画面の文字には、古い言葉が残る（例：web の画面の「人の確認待ちです」、`fake.py` のコメントの「偽物」、`.feature` のテストの仕様、契約のスキーマの説明文）。用語集は「文書・コード・画面ではここの言葉を使う」と決めているので、残っている場所を pull request の説明に書き、直すかは人に聞く。
