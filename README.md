# qata-agent-lab

qata をまるごとコピーし、それを材料に、AI エージェントへの指示（ルール・スキル・レビュー役のエージェント・決めたことなどの文書）の書き方だけを改善する場所です。

- 元のプロジェクト：[masakazu2025/qata](https://github.com/masakazu2025/qata)（Windows のデスクトップアプリに対して、日本語の手順からテストを作り、自動で再生し、結果を確認するツール）
- 立ち上げの issue：[masakazu2025/qata#71](https://github.com/masakazu2025/qata/issues/71)
- 方針の元になったメモ：[plan.md](plan.md)
- やること：このリポジトリの issue。優先順はボード <https://github.com/users/masakazu2025/projects/5>（qata のボードとは別）
- 移植用の指示書：[instructions/](instructions/)

## なぜ分けたか

qata では、アプリの実装と、エージェントへの指示の改善を同じリポジトリで同時に進めてきました。その結果、指示の手直しに時間を取られて実装が止まりがちになり、どちらも速く進みませんでした。また、スキル・レビュー結果・issue が、人が読むと分かりにくい文になっていました。

そこで、実装は qata でいまの形のまま進め、指示の書き方の改善はここで切り離して進めます。

## qata との関係

- **同期しません。** ここにあるのは、2026-11-19 時点のコピーです。以降、qata の変更は取り込みません。
- **qata に戻すのは必須ではありません。** うまくいけば、改善した中身を qata に移します。場合によっては、ここで作った指示一式に文書を移して、qata を作り直すことも考えます。
- コードも含めて全部コピーしたのは、量がないと、作った書き方の決まりがいろいろな文書に通用するか確かめられないためです。

## 進め方

- **小さいところから、少しずつ進めます。** 一か所の言葉、一つの雛形、一つのスキルのように、すぐ終わって結果を見比べられるものから始めます。全体の作り（文書の置き場所・工程の分け方など）は、小さな作業で書き方が固まってから扱います。
- コピーの中身は、できるだけ直しません。ただし、文書どうしで食い違っているところは直します。
- やることは、このリポジトリの issue に置きます。

## 移植用の指示書

あとで qata に移すことを考えて、**issue を一件終えるごとに、やったことを指示書として [instructions/](instructions/) に書きます。** 指示書は、ここでの経緯を知らない AI エージェントが、本物の qata に同じ変更を入れられるように書きます。書き方は [instructions/README.md](instructions/README.md) にあります。

ここで直したファイルそのものを qata に写すのではなく、指示書を渡して入れ直してもらう形にします。qata はこのあとも進むので、ここでのコピーと本物の中身がずれていくためです。

## やることの一覧

### はじめにやる（小さいもの）

上から順に進めます。どれも一つのセッションで終わる大きさです。

| 順 | やること | 何を見るか |
| --- | --- | --- |
| 1 | 内輪の言葉「関門」を、一般の言葉に置き換える | 用語集と、それを使う文書 |
| 2 | issue の雛形を、読む人に合わせて書き直す | `qata/.github/ISSUE_TEMPLATE/` |
| 3 | スキルを一つ（session-start）、読みやすく書き直す | `qata/.claude/skills/session-start/` |
| 4 | pull request の説明の雛形を作る | いまは雛形がない |
| 5 | 文書どうしの食い違いを洗い出し、一覧にする（直すのは一件ずつ別に） | `qata/` の文書全体 |

### あとでやる（大きいもの）

小さな作業で書き方が固まってから扱います。

- 書き方の決まりを一つにまとめる
- 親の README から一続きに読めるよう、入口と全体の図を作る
- 決めたこと・改善案（`docs/decisions.md`・`docs/ideas.md`）を 1 件 1 ファイルに分け、種別と優先順位を持たせた一覧を作る
- 工程ごとにスキルを分けるかを決める（qata の [#59](https://github.com/masakazu2025/qata/issues/59) と重なる）
- 文書を親に集めるか、子にも置くかを決める
- コーディング規約・おすすめの設計パターンが要るかを決める（qata の [#24](https://github.com/masakazu2025/qata/issues/24) と重なる）
